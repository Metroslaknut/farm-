# Risks and known limitations

Severity = impact × likelihood **if left as is at public launch** (H high, M medium, L low). "Gate" = should be resolved or consciously accepted before launch.
Owners/dates are for the team to fill in. Items from earlier Parts are repeated here so the register is in one place.

## Must be decided or done before public launch (gates)

| #   | Risk / limitation                                                                                    | Sev.                 | Why it matters                                                                                                                                         | Recommended action                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **No independent security review.** All evidence here is the project's own automated tests and audit | H                    | Self-review misses what the authors cannot see; the matrices prove status-code behaviour with empty/ghost inputs, not every object-level business rule | External penetration test of a staging environment (web, API, realtime, mobile) and a code review of auth, finance and chat; fix findings before launch        |
| R2  | **No malware scanning / file-content validation** (links to CDN-hosted files only)                   | M–H                  | A malicious PDF/image reaches administrators (registration documents) or users                                                                         | Implement the strategy in [security-audit.md](security-audit.md#malware-scanning-strategy-not-implemented--decision-required-before-accepting-user-files)      |
| R3  | **No real payment provider** (`PAYMENT_PROVIDER=none`); finance logic is proven against a mock       | H if payments launch | Real providers differ (partial captures, delayed webhooks, duplicate refunds, currency rounding, settlement reports)                                   | Keep payments off until an adapter is built, run a provider sandbox test pass with this suite as the template, get legal/provider review (stored-value/escrow) |
| R4  | **No self-service account deletion / data export**                                                   | M (legal)            | PDPA data-subject rights; Apple/Google store requirements                                                                                              | Design with legal (retain financial/audit records, erase the rest), build before store submission                                                              |
| R5  | **No staging deployment yet; Atlas PITR restore not drilled; alerts not created**                    | M–H                  | Production behaviour (TLS, proxy hops, WebSocket routing, backups) is unverified                                                                       | Run the release procedure on staging, record the verification script output and the first restore drill ([../ops/](../ops/README.md))                          |
| R6  | **Realtime is single-instance** (in-memory adapter)                                                  | M when scaling       | Events reach only clients connected to the same instance                                                                                               | Add the Redis adapter + sticky sessions before running >1 API instance; clients already resync after gaps                                                      |

## Accepted / monitored limitations

| #   | Limitation                                                                                                             | Sev.        | Notes                                                                                                                                                                                                                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | Rate limits are **per instance and per IP** (in-memory)                                                                | M           | Shared NATs can hit limits; several instances multiply the budget; a Redis store fixes both. Sign-in is additionally protected by account lockout. No CAPTCHA/bot management/WAF — put the API behind a CDN/WAF with DDoS protection                                                                                          |
| L2  | **Refresh token in `sessionStorage`** (web)                                                                            | M           | Readable by injected script (XSS). Mitigated by strict CSP (no inline scripts), React escaping (verified in browser e2e), https-only URLs, short access-token lifetime, refresh rotation + reuse detection. An httpOnly cookie design would trade this for CSRF protection — decision recorded in `docs/architecture/auth.md` |
| L3  | **CSP allows inline styles** (`style-src 'unsafe-inline'`)                                                             | L           | Needed by the design system's style attributes; styles cannot run code. Remove when components move to classes                                                                                                                                                                                                                |
| L4  | **Every authenticated request costs 4 database reads** (token → session → user → roles)                                | L           | Deliberate: immediate revocation. See load results for the lever and its trade-off                                                                                                                                                                                                                                            |
| L5  | **Partial refunds unsupported**; refunds are full-amount only                                                          | L           | A mismatching provider amount is flagged, never applied. Product decision                                                                                                                                                                                                                                                     |
| L6  | **`MFA_ENCRYPTION_KEY` cannot be rotated** without a re-encryption migration                                           | M           | Documented in the incident runbook; write the migration before it is needed                                                                                                                                                                                                                                                   |
| L7  | Admin **KYC documents are external links**                                                                             | M           | F1 restricts hosts; see R2 for content risk                                                                                                                                                                                                                                                                                   |
| L8  | Notifications are folded/aged out (180 days) and **offer expiry does not notify**                                      | L           | By design / backlog                                                                                                                                                                                                                                                                                                           |
| L9  | **Message text is stored unencrypted** (like other business data); moderators see only reported evidence               | M (privacy) | Encryption at rest is provided by Atlas; field-level encryption would be a larger change                                                                                                                                                                                                                                      |
| L10 | `pnpm audit` data comes from the registry; two high advisories in mobile build tooling are **waived until 2027-01-31** | L           | See [audit-waivers.json](audit-waivers.json); re-review on every release                                                                                                                                                                                                                                                      |
| L11 | Analytics dashboards are cached **per instance** and statuses are "as of now"                                          | L           | Part 16 documentation                                                                                                                                                                                                                                                                                                         |

## Limits of the testing itself

| #   | Gap                                                                                                                                                                                                                                                                                                     | Effect                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| T1  | **Test coverage percentage was not measured** (no coverage run); confidence comes from the matrices, property/concurrency tests and the mutation checks listed in each Part's report                                                                                                                    | Untested branches exist; do not read the test counts as coverage                                      |
| T2  | Authorization matrices use ghost ids and empty bodies, so they prove **"nothing succeeds that should not"**, not that every business rule inside a successful path is right; object-level rules rely on the feature suites and the IDOR sample (orders, payments, negotiations, animals, conversations) | A rule bug inside a feature could still exist                                                         |
| T3  | End-to-end: **6 browser scenarios, web only**; no admin-MFA flow, no mobile device tests, no cross-browser matrix (Chrome/Chromium only), no accessibility audit tooling                                                                                                                                | UI regressions outside these paths are caught only by component tests                                 |
| T4  | Load test: in-memory MongoDB on the same machine, short runs, one scenario at a time (see [load-test-results.md](load-test-results.md))                                                                                                                                                                 | No capacity claim can be made                                                                         |
| T5  | The static scans (secrets, XSS sinks, TLS flags) are pattern based                                                                                                                                                                                                                                      | A cleverly obfuscated problem would pass; they catch the common mistakes                              |
| T6  | `git` history was not available in the authoring environment, so the CI secret scan over history has not been run                                                                                                                                                                                       | Run it once on the real repository                                                                    |
| T7  | The Dockerfiles, GitHub workflows (CI/release/EAS) and the Atlas-side controls were written but **not executed** (no Docker/GitHub/Expo/Atlas accounts)                                                                                                                                                 | First real run may need fixes (one workflow YAML error was already found and fixed by `format:check`) |

## Re-test triggers

Re-run the full set (`pnpm check`, `pnpm e2e`, `pnpm qa:audit`, `pnpm load`) and review the route/permission snapshots on: any new endpoint or permission, any change to authentication, sessions, finance or realtime code,
dependency upgrades, a new provider adapter, an infrastructure change (proxy, CDN, database tier), and before every production release.
