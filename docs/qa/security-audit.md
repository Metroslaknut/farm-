# Security audit — checklist, evidence, findings

Legend: **Verified** = covered by an automated test that fails if the control is removed (mutation-checked where noted) · **Partial** = covered with stated limits · **Open** = not implemented / needs a decision (see [risks-and-limitations.md](risks-and-limitations.md)).
Test files are under `services/api/test/` unless stated. "Matrix" tests enumerate every route of the running app (`qa/route-inventory.ts` records router mount paths), so a new endpoint cannot escape them: the route list and the permission→route map are snapshots that fail on any change until reviewed.

## Input handling

| Item              | Status                                  | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Input validation  | **Verified**                            | strict Zod schemas on every endpoint (unknown fields rejected). `qa/fuzz`: **every route × 12 hostile bodies × 3 callers (anonymous, farmer, super admin)**, **× 5 hostile query strings**, **× 8 hostile path parameters** — never a 5xx, errors are JSON, no stack traces / driver errors / paths leaked (mutation-checked: an injected throw is detected). Bodies tried: `{}`, `[]`, `null`, strings, truncated JSON, wrong content type, prototype-pollution keys, Mongo operators, 500-level nesting, 150 kB payloads, wrong types, hostile Unicode/markup |
| Injection (NoSQL) | **Verified**                            | `qa/security-dynamic`: operator objects (`$ne`, `$gt`, `$regex`, `$in`, `$exists`) in credentials, tokens and query strings are rejected or ignored, never evaluated; static scan: no `$where`/`$function`/`mapReduce`/string-built queries in the API; `qa/fuzz`: no prototype pollution afterwards                                                                                                                                                                                                                                                            |
| XSS               | **Verified**                            | static scan of web + mobile: no `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `document.write`, injected WebView scripts; every `target="_blank"` has `noopener`; **browser e2e**: markup in a farm name and in a chat message is displayed as text, no script runs, no dialog opens; all user URLs must be `https` (every `z.url()` in the validation package is restricted — scanned) and media URLs obey a host allow-list (16 hostile URL forms tested on 3 endpoints, F1)                                                                |
| CSRF              | **Verified (not applicable by design)** | tokens travel only in the `Authorization` header; the server never sets or reads a cookie (static scan + test of every auth response); a cross-site request carrying only cookies is 401 on four state-changing routes; CORS grants nothing to unlisted origins and never `credentials`; the web client keeps tokens in memory/sessionStorage, never `localStorage` or cookies                                                                                                                                                                                  |
| Upload validation | **Partial**                             | the API stores **links**, not files: https only, host allow-list, kind/mime checks, count limits; video upload size/duration limits and signed provider webhooks (`video`, `animals`, `qa/security-dynamic`). **No malware scanning exists** — see the strategy below                                                                                                                                                                                                                                                                                           |

### Malware scanning strategy (not implemented — decision required before accepting user files)

FARM+ never receives or serves user file bytes: photos, documents and video live on the CDN / object storage / Cloudflare Stream, and the API accepts only
`https` links on `MEDIA_ALLOWED_HOSTS`. The residual risk is therefore on the storage side and in what administrators open (registration documents).
Required before launch, in this order:

1. **Scan at the storage layer**: upload to a _quarantine_ bucket, scan (ClamAV / the provider's malware scanning, e.g. Cloudflare/AWS malware protection), and only then publish to the public bucket; never serve unscanned objects.
2. **Content checks**: allow-list types (JPEG/PNG/WebP/PDF, MP4 via Stream), verify magic bytes not the extension, strip EXIF/GPS from photos, size caps, re-encode images.
3. **Serve safely**: from a separate cookie-less origin, `X-Content-Type-Options: nosniff`, `Content-Disposition: attachment` for documents, no inline HTML/SVG.
4. **Administrator workflow**: open registration documents through a sandboxed previewer, never as a raw link in the admin origin (F1 already limits links to the CDN host).
5. Log and alert on scan failures; define the takedown procedure.

## Other checks performed

- **Performance as a security property**: `qa/query-plans` runs `explain()` on 22 hot queries (notifications, chat, orders, listings, animals, ledger, webhook lookups, cleanup jobs) — none scans a collection (F2 found and fixed).
- **Concurrency**: parallel acceptance/checkout/payment/refund/payout races across `marketplace`, `orders`, `shop`, `finance`, `qa/financial-qa`.
- **Realtime**: `realtime` (18 tests): authenticated handshake, per-room authorization, eviction on membership change, abuse limits, recovery.
- **Static/format/type**: strict TypeScript, ESLint, Prettier (also validates workflow YAML).

## What this audit did NOT do

Independent penetration testing, a third-party code review, fuzzing with a coverage-guided engine, a DAST scan of a deployed environment, infrastructure
configuration review (Atlas, DNS, CDN, load balancer), mobile binary analysis, or a formal threat model workshop. Recommended before public launch (see risks).
