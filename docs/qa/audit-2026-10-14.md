# FARM+ — Second full-system QA, bug-fix and security audit

**Date:** 14 Oct 2026 · **Environment:** macOS arm64, Node 26.5, pnpm 12.11.2, in-memory MongoDB (mongodb-memory-server), mock payment / video / AI / SMS / e-mail / shipping providers, local Chrome for browser tests · **Source control:** no git history; changes were identified by diffing against a full source snapshot taken before any edit.

> **This report does not state that FARM+ is secure or ready for production.** It records what was tested here, what was found and fixed, and what could not be tested. AI-assisted work: review every change before relying on it.

## 1. Executive summary

- Builds on the 13 Oct audit ([full-audit-report.md](full-audit-report.md)), which covered records/AI, auth, media, orders/inventory. This pass focused on **finance, shop/marketplace, chat/realtime/community/analytics, platform security and the Web/Mobile clients**, plus that audit's "suspected, not verified" items.
- **Baseline (before changes):** typecheck, lint, tests (API 1021, Web 278, Mobile 157), build and dependency policy passed; `format:check` failed only on the generated `docs/acceptance/evidence/api-journey.json` (pre-existing; the acceptance test rewrites it each run).
- **16 defects confirmed and fixed** (0 Critical, 1 High, 9 Medium, 6 Low). Each was reproduced first by an automated test that failed, then fixed with the smallest change.
- **After fixes:** API **1033/1033**, Web **292/292**, Mobile **157/157**, typecheck, lint, build, browser e2e **11/11**, dependency policy 0 failing.
- **9 items need a product/security decision** (section 6) — notably MFA enrolment without re-authentication and binding an unverified e-mail/phone to an account.
- **Recommendation:** suitable for staging/UAT after code review. **Not recommended for production** until section 6 is decided and section 8 is tested.

`services/api` modules finance, orders, shipping, products (cart, checkout, reviews, moderation), marketplace (listings, negotiations), chat, realtime (Socket.IO), notifications, community, analytics/exports, auth/session/MFA/verification, admin/roles/settings/registrations/audit-logs, farms/members, media webhooks/uploads, app/middleware/config. `apps/web` session handling, wallet, shop, cart, inbox. `apps/mobile` session, token storage, deep links, checkout. `packages/api-client`, `packages/validation`. `services/worker` is a 138-line skeleton (no queue backend) — nothing to audit.

## 3. Defects found and fixed

| ID  | Sev    | Defect (expected → actual)                                                                                                                                        | Root cause                                                                        | Fix                                                                                                                            |
| --- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| W1  | High   | Web: a network error, 429 or 5xx during token refresh signed the user out (laptop wake, rate limit)                                                               | any refresh error cleared the session (Mobile was fixed on 13 Oct, Web was not)   | `apps/web/src/api.ts`: only 400/401/403 end the session (same rule as Mobile)                                                  |
| S1  | Medium | Seller could pause an approved product, change title/photos/category, and resume it **live without review**                                                       | re-review rule applied to `ACTIVE` only                                           | `products.service.ts` + `PRODUCT_TRANSITIONS`: material edit of a `PAUSED` product also goes to `PENDING_REVIEW`; spec updated |
| F1  | Medium | Refunding an under/over-payment parked in suspense left suspense permanently off (e.g. −2,500 THB)                                                                | refund journal used `payment.amountMinor` instead of the amount received/refunded | `ledger.ts postRefund`: reverses `refund.amountMinor`                                                                          |
| F2  | Medium | Order cancelled between "order PAID" and "payment applied" (race or crash) stayed `REFUND_PENDING` forever with **no refund**; reconcile repair did not create it | refund is only opened for an applied payment; nothing re-checked after applying   | `payments.service.ts finalizePayment`: after applying, an order already in `REFUND_PENDING` gets its refund (idempotent)       |
| F3  | Medium | A finance admin who is a manager of the selling farm could approve refunds on that farm's orders                                                                  | self-approval check compared only `order.sellerId`                                | `refunds.service.ts`: also refuses seller-side farm members                                                                    |
| F4  | Medium | Withdrawal retried with the same idempotency key but a different amount was answered with the old (cancelled) withdrawal as success                               | key replay ignored the amount                                                     | server: 409 `IDEMPOTENCY_KEY_REUSED`; Web wallet: new key after a 4xx (W2)                                                     |
| W2  | Medium | (client side of F4) Web kept the key after a 409, so retries replayed                                                                                             | key rotated only on success                                                       | `WalletPage.tsx`: rotate after 4xx; keep after network/5xx                                                                     |
| C1  | Medium | A moderator could lift their **own** chat restriction                                                                                                             | no self check in `liftRestriction`                                                | 403 `SELF_MODERATION`                                                                                                          |
| C2  | Medium | A moderator who is owner/manager of the farm in a conversation could resolve reports on it                                                                        | only reporter/reported compared                                                   | also refuses anyone with access to the conversation                                                                            |
| W3  | Medium | Web chat: after missing > 50 messages while offline, the gap stayed until reload                                                                                  | catch-up ignored `hasMore`                                                        | `MessagesPage.tsx`: follows pages (bounded to 20)                                                                              |
| W4  | Low    | Web "Add to cart" replaced the cart quantity (add 2, then 3 → 3)                                                                                                  | page used the "set quantity" endpoint as "add"                                    | `ProductPage.tsx`: adds to the current line; limits checked on the total                                                       |
| W5  | Low    | Web cart fetched a shipping quote on every keystroke of the province; checkout could use the previous province's quote (server refused it)                        | no debounce                                                                       | `CartPage.tsx`: 400 ms debounce; "Place order" disabled until the quote matches the typed province                             |
| M1  | Low    | Buyer could exceed the 20-open-negotiation cap by reopening closed ones                                                                                           | cap checked only on first offer                                                   | `negotiations.service.ts`: same check on reopen                                                                                |
| C3  | Low    | Analytics dashboard and CSV showed timestamps as UTC dates (00:00–06:59 Bangkok → previous day)                                                                   | `toISOString().slice(0,10)`                                                       | `bangkokDay()` for timestamps; date-only fields unchanged                                                                      |
| C4  | Low    | Un-liking a post that was later hidden returned 404 and kept the reaction                                                                                         | visibility check before delete                                                    | allowed when the user has a reaction; hidden content otherwise stays 404                                                       |
| C5  | Low    | Socket join with an upper-case conversation id joined a room that never received messages                                                                         | room name used the raw id                                                         | canonical lower-case id on join/leave                                                                                          |

(16 defects; F4 and W2 are the server and client sides of the same withdrawal problem.)

## 6. Open items needing a decision (not fixed)

| Item                                                                                                                                                                                                                                                               | Sev                                | Why not fixed                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ------------------------------------------------------------------------------- |
| MFA enrolment (`/auth/mfa/setup`, `/enable`) needs no password and marks the current session MFA-verified: a stolen access token can bind the attacker's authenticator, lock out the owner, and (for an un-enrolled staff user) unlock admin permissions           | Medium                             | requires a password field in the Web/Mobile enrolment screens (API + UI change) |
| Registering with someone else's e-mail plus own phone (or vice versa): verifying one channel activates the account, the unverified identifier then works for login and for "add farm member by e-mail", and blocks the real owner from registering                 | Medium                             | needs a rule: verify each identifier before use, or drop the unverified one     |
| Staff with `farms.manage` can add themselves (or a proxy) as farm manager and gain `listings.manage`, which platform staff are meant not to have                                                                                                                   | Medium-Low                         | policy decision on staff membership                                             |
| Seller can self-report a shipment "delivered", which starts auto-confirm and payout release; no dispute flow                                                                                                                                                       | Medium                             | business decision (orders.md says delivered "by carrier")                       |
| Listing pause → edit → resume skips re-review (allowed by current marketplace.md and its test)                                                                                                                                                                     | Medium                             | spec change; product equivalent S1 was fixed because the spec required it       |
| Web "Duplicate tab" copies the single-use refresh token; both tabs refresh and the server revokes the session as token reuse                                                                                                                                       | Medium (UX)                        | needs cross-tab lock or server grace window                                     |
| Concurrent double checkout of the same cart can create two order sets (stock held until expiry)                                                                                                                                                                    | Low-Med, plausible, not reproduced | needs cart lock or idempotency key                                              |
| Web wallet withdrawals list stops at 10; some errors swallowed silently (cancel withdrawal, remove cart line, dismiss recommendation)                                                                                                                              | Low                                | visible UI change                                                               |
| Smaller: abandoned payment attempts not cancelled at provider; reviews of a suspended product readable by id; MFA login token not bound to password change; socket room join can race with member removal; admins can remove non-protected roles from super admins | Low                                | low risk; listed for backlog                                                    |

Items from the 13 Oct report section 6 remain open unless listed above as fixed.

## 7. Security findings (OWASP view)

- **A01 Broken access control:** fixed F3, C1, C2 (self-approval / self-moderation), S1 (moderation bypass). Open: staff farm membership, MFA enrolment. Reviewed and sound: BOLA on orders/payments/wallets/chat/notifications, admin route permissions, farm role limits, analytics permission scoping and cache keys.
- **A04 Insecure design:** fixed F2, F4, M1. Open: seller-reported delivery, double checkout.
- **A07 Authentication:** fixed W1 (availability). Open: MFA enrolment re-auth, unverified identifiers, duplicate-tab refresh. Sound: JWT pinning/claims, refresh rotation + reuse detection, TOTP replay, reset tokens.
- **A03 Injection / XSS:** none found — `$regex` inputs escaped, strict Zod schemas, no `dangerouslySetInnerHTML`, user URLs https-only, CSV formula cells prefixed.
- **A05 Misconfiguration:** CORS exact-origin without credentials, Helmet/HSTS, `TRUST_PROXY` hop count, body limits, generic 5xx errors — sound in code; production values not verified.
- **A08/A10 Integrity, SSRF:** webhooks HMAC over raw body, constant-time, ±300 s window; outbound calls only to fixed provider hosts.
- **A06 Components:** unchanged (5 advisories, 0 failing policy).

No secrets, `.env` contents or customer data were read or committed. No real payments, refunds or withdrawals were made.
