# FARM+ — Full system QA, bug-fix and security audit

**Date:** 13 Oct 2026 · **Environment:** macOS arm64, Node 26, in-memory MongoDB (mongodb-memory-server), mock payment / video / AI / SMS / e-mail providers, local Google Chrome for browser tests · **Source control:** the working copy has no git history; changed files were identified by comparing SHA-1 checksums of all 711 source files taken before the audit started.

> **This report does not state that FARM+ is secure or ready for production.** It records what was tested in this environment, what was found and fixed, and what could not be tested. AI-assisted work: every result below should be reviewed by the team before it is relied on.

## 1. Executive summary

- **Baseline (before any change):** typecheck, lint, format, unit/integration tests (API 987, Web 272, Mobile 155), build, browser e2e (7) and the dependency-audit policy all passed. Passing tests did not mean the absence of defects: six focused reviews (records/AI, authentication, media/community, orders/inventory, Web, Mobile) found the defects below.
- **28 defects confirmed and fixed**, each reproduced first by a failing automated test (or, for 1 helper, a unit test) and then fixed with the smallest change. Severity: **6 High, 15 Medium, 7 Low**. No defect was found that we would class as Critical.
- **After the fixes:** every check passes again — API **1009/1009** (+22 regression tests), Web **278/278** (+6), Mobile **157/157** (+2), build, e2e **7/7**, audit policy **0 failing** — with no layout, colour, typography or navigation change.
- **Not fixed (documented):** 14 lower-risk or unconfirmed items (section 6). **Blocked:** everything that needs a real external provider or a deployed environment (section 8).
- **Recommendation:** suitable for **staging and user-acceptance testing** after code review of these changes. **Not recommended for production** until the blocked items in section 8 are tested and an independent penetration test is done.

## 2. Repository and modules inspected

pnpm monorepo: `apps/web` (React 19, Vite), `apps/mobile` (Expo / React Native), `services/api` (Express 5, Mongoose 9, Zod 4, Socket.IO), `services/worker`, `packages/{shared-types,shared-utils,validation,api-client,config}`, `e2e/` (Playwright, load test).

API modules reviewed: auth, sessions, MFA, verification, RBAC and roles, farms and farm access, animals, records (weights, health, feeding, breeding), history, AI assessments, community and moderation, media / video / live, marketplace (listings, negotiations, reservations), orders, shop (products, cart, inventory, reviews), finance (payments, ledger, wallet, commissions), rate limiting. Web and Mobile: payment, checkout, records forms, admin pages, session handling.

## 3. Defects found and fixed

Severity: **High** = data exposure, privilege or integrity failure with a realistic path; **Medium** = wrong data or a broken user flow; **Low** = minor or over-restrictive behaviour.

| ID     | Sev    | Defect (expected → actual)                                                                                                                                                                    | Root cause                                                                                             | Fix                                                                                                                   |
| ------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| R1     | High   | Farm workers/viewers (no `expenses.read`) received recorded costs and net-over-cost figures inside AI assessments                                                                             | assessment DTO ignored the reader's farm permissions                                                   | `ai.service.ts`: costs, net-over-cost and a cost-based narrative are withheld unless the reader holds `expenses.read` |
| A1     | High   | Legacy `PUT /roles/:key/permissions` let a `permissions.manage` holder rewrite roles carrying permissions they lack, and did not require MFA / end sessions when a role became privileged     | the legacy path did not share the rules of the newer admin role editor                                 | `role.service.ts`: both paths use one `replaceRolePermissions` helper (subset check, MFA flag, session revocation)    |
| O1     | High   | Inventory cleanup only ever looked at the first 500 old reservations, so once 500 were settled, orphan / paid / cancelled orders were never repaired                                          | query returned settled rows too, with a fixed limit                                                    | `inventory.service.ts`: aggregation selects only unsettled, actionable rows                                           |
| O2     | High   | A payment and a cancellation settling the same order at once recorded **both** a sale and a release (stock and reserved counts wrong)                                                         | check-then-act; the uniqueness index is per movement type                                              | reserve row is atomically claimed (`settledBy`) before a sale or release is applied                                   |
| O3     | High   | An animal reservation could be released by cleanup or a cancel just after an order attached to it (animal back on sale while an order exists); an expired hold could be attached and extended | release writes re-checked only the negotiation, not `reservation.orderId`; attach did not check expiry | release writes require `reservation.orderId: null`; attach requires an unexpired hold                                 |
| M1     | High   | A moderator removing a **live** stream directly (not via a report) did not stop the broadcast                                                                                                 | route did not pass the video provider to the service                                                   | `moderation.routes.ts` passes `ctx.video`                                                                             |

| M2     | Medium | A moderator could dismiss reports about their **own** content                                                                                                                                 | self-moderation check only on hide/remove                                                              | dismiss checks `targetAuthorId`                                                                                       |

| R5     | Medium | Between 00:00 and 07:00 Thai time, today's date was refused as "in the future" (records, animals, farms)                                                                                      | "today" computed in UTC                                                                                | `packages/validation/src/dates.ts` `thaiToday()` used by the schemas                                                  |
| R7     | Medium | Records of an archived animal could still be corrected, voided or get attachments (documented as read-only)                                                                                   | only creation checked the archive state                                                                | `record-core.ts` checks the animal on correct / void / attach / detach                                                |
