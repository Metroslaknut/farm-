# FARM+ assistant (help Q&A) — design for PR 4

Status: **proposal, waiting for approval** (nothing below is built yet). PR 5 (contextual tips) and PR 6 (assistant
actions) are separate and not covered here.

## What it does, and does not

- Answers "how do I…" questions about **using FARM+**, in Thai or English, from the help articles, the guided-tour
  texts and a catalogue of app pages. Example: "เพิ่มไก่ยังไง", "สมัครแล้วเข้าไม่ได้", "ขายวัวต้องทำอะไรบ้าง".
- Every answer cites the help articles it used and may offer **links to app pages from the catalogue only** and
  **tours that exist**. It never invents a URL.
- It does **not**: read or change anyone's farm, animal, order or account data; give veterinary, legal or financial
  advice; answer unrelated questions. Unknown → says so and points to `/help` or "contact the team".
- **Off by default** (admin switch). Guests get the same help search without the AI (no model call).

## How it answers (retrieval first, model second)

1. **Knowledge index (built at build time, no database).** The help articles (`apps/web/src/help/content/{th,en}`,
   already parsed by `help/parse.ts`) are split by heading/step into small chunks; tour step texts and a **route
   catalogue** (path, Thai/English page name, permission needed, related help slug) are added. The index is a JSON file
   shipped with the API (`services/api/src/modules/assistant/index.json`), regenerated by a script and checked by a
   test so it cannot go stale.
2. **Search.** BM25 over Thai word segments (`Intl.Segmenter('th')`, which the help search already uses) and English
   words; top 5 chunks. No embeddings in this PR (can be added later if the eval shows a need).
3. **Model call** (only when signed in, the switch is on and the person is under their daily limit): one request with
   a fixed system prompt (rules below) and the 5 chunks as **data**; the model returns structured JSON:
   `{ answer, citations: [slug], links: [routeId], tours: [tourId] }`.
4. **Validation before anything is shown.** `citations` must be among the chunks sent, `links` must be catalogue ids
   the person may open (checked with their permissions), `tours` must exist; anything else is dropped. Answer length
   capped. If the output does not validate, the person gets the search results without an AI answer.
5. **No model / over limit / AI off / guest** → the same endpoint returns the top articles only ("search mode").

## API

`POST /api/v1/assistant/ask` — `{ message (≤ 500 chars), locale, context: { route, farmId? } }` →
`{ mode: 'ai' | 'search', answer?, citations: [{ slug, title }], links: [{ label, route }], tours: [tourId] }`.

- Signed-in only for `ai` mode; guests are served `search` mode (route stays public, rate limited separately).
- Own rate limit (e.g. 20 questions / 15 min / person, 60 / 15 min / address), independent of login limits.
- `context.route` only helps ranking (articles related to the page first); `farmId` is ignored in this PR.
- Route review: new route → `routes.snapshot.txt`, allowlist entry with reason (public search mode), permission
  matrix unchanged.

## Model, cost and limits (reusing the existing AI layer)

- Uses the **existing provider seam** (`modules/ai/provider.ts`: `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`, timeout),
  so no new secret and the same mock for tests. Model: the configured `AI_MODEL` (today `claude-sonnet-5-5`); an
  optional `AI_ASSISTANT_MODEL` can override it.
- **Usage and cost**: every call is written to the existing `ai_usage_logs` with `feature: 'assistant'` (tokens,
  cost from the existing per-million settings, latency, error code), so the existing admin AI page shows it.
- **Limits** (new admin settings, next to the AI ones): `assistant.enabled` (default **false**),
  `assistant.dailyLimit` (whole platform), `assistant.perUserDaily` (e.g. 20).
- Rough cost at Sonnet rates ($2 / $10 per million tokens): ~2,500 input + ~300 output tokens per question ≈
  **฿0.3 per answer**; 1,000 questions a day ≈ ฿300/day. The daily limit caps it.

## Safety

- **Personal data redaction before the model**: phone numbers, e-mail addresses, 13-digit ID numbers, bank account
  numbers and LINE ids in the question are replaced (`[เบอร์โทร]`, …) — unit-tested with Thai formats.
- **Prompt injection**: the question and the chunks are passed as data inside clear delimiters; the system prompt says
  they are never instructions; the system prompt is never echoed; output is schema-checked (above) so a manipulated
  answer cannot add links or tours.
- **Scope rules** in the system prompt: only FARM+ usage; no veterinary/legal/financial advice (same disclaimer as the
  AI assessment); say "ไม่ทราบ" instead of guessing; answer in the question's language; short (≤ 6 lines + steps).
- Nothing the person asks is stored except the usage log (no question text by default; an opt-in admin setting could
  keep redacted questions for 30 days to improve the help — off by default).

## Web

- A "ถามผู้ช่วย FARM+" panel opened from the help button in the header and on `/help` (lazy chunk, like the tour
  overlay). Shows the answer, the cited articles, page links and "start the tips" buttons; "ไม่ช่วย" feedback reuses
  the help feedback endpoint. Thai and English texts; keyboard and screen-reader accessible.
- When `mode: 'search'`, the panel shows the top articles (same look) with a note that answers are switched off.

## Quality check (before switching it on)

- A **golden set of ≥ 30 Thai questions** written the way farmers type ("รหัส sms ไม่มา", "ทำไมสร้างฟาร์มไม่ได้",
  "เพิ่มไก่ยังไง"…) with the expected article. **Target: the right article in the top 3 for ≥ 90%** — this runs in CI
  on the search step alone (no model, no cost).
- The model step is tested with the mock provider (validation, dropped links, redaction, limits, usage log). A small
  manual run against the real model (a few cents) before turning it on in staging — with your go-ahead.

## Deliverables of PR 4

API module `assistant` (index builder, search, ask service, routes), admin settings, usage logging, web panel,
golden-set test, unit tests for redaction/validation/limits, e2e for the panel (search mode and mocked AI mode),
`docs/architecture/assistant.md` updated to "built". No database migration (settings and usage log already exist).
