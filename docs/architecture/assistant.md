# FARM+ assistant (help Q&A)

Status: **built (PR 4), off by default.** Approved 28 Nov 2026 with these decisions: the configured `AI_MODEL`; 20 AI
answers per person per day and 1,000 per platform per day; **question text is never stored**. PR 5 (contextual tips) and
PR 6 (assistant actions) are separate and not covered here.

Code: `services/api/src/modules/assistant/` (`build-index.ts`, `help-index.json`, `knowledge.ts` search, `redact.ts`,
`catalog.ts` pages and tours, `assistant.service.ts`, `assistant.routes.ts`); web panel
`apps/web/src/components/assistant/AssistantPanel.tsx` on `/help`. After editing a help article run
`pnpm --filter @farmplus/api assistant:index` (a test fails while the index is stale).

## What it does, and does not

- Answers "how do I…" questions about **using FARM+**, in Thai or English, from the help articles, the guided-tour
  texts and a catalogue of app pages. Example: "เพิ่มไก่ยังไง", "สมัครแล้วเข้าไม่ได้", "ขายวัวต้องทำอะไรบ้าง".
- Every answer cites the help articles it used and may offer **links to app pages from the catalogue only** and
  **tours that exist**. It never invents a URL.
- It does **not**: read or change anyone's farm, animal, order or account data; give veterinary, legal or financial
  advice; answer unrelated questions. Unknown → says so and points to `/help` or "contact the team".
- **Off by default** (admin switch). Guests get the same help search without the AI (no model call).

## How it answers (retrieval first, model second)

1. **Knowledge index (built at build time, no database).** The help articles (`apps/web/src/help/content/{th,en}`,
   already parsed by `help/parse.ts`) are split by heading/step into small chunks; tour step texts and a **route
   catalogue** (path, Thai/English page name, permission needed, related help slug) are added. The index is a JSON file
   shipped with the API (`services/api/src/modules/assistant/help-index.json`), regenerated by a script and checked by a
   test so it cannot go stale.
2. **Search.** BM25 over Thai word segments (`Intl.Segmenter('th')`, which the help search already uses) and English
   words; top 5 chunks. No embeddings in this PR (can be added later if the eval shows a need).
3. **Model call** (only when signed in, the switch is on and the person is under their daily limit): one request with
   a fixed system prompt (rules below) and the 5 chunks as **data**; the model returns structured JSON:
   `{ answer, citations: [slug], links: [routeId], tours: [tourId] }`.
4. **Validation before anything is shown.** `citations` must be among the chunks sent, `links` must be catalogue ids
   the person may open (checked with their permissions), `tours` must exist; anything else is dropped. Answer length
   capped. If the output does not validate, the person gets the search results without an AI answer.
5. **No model / over limit / AI off / guest** → the same endpoint returns the top articles only ("search mode").

## API

`POST /api/v1/assistant/ask` — `{ message (≤ 500 chars), locale, context: { route, farmId? } }` →
`{ mode: 'ai' | 'search', answer?, citations: [{ slug, title }], links: [{ label, route }], tours: [tourId] }`.

- Signed-in only for `ai` mode; guests are served `search` mode (route stays public, rate limited separately).
- Own rate limit (e.g. 20 questions / 15 min / person, 60 / 15 min / address), independent of login limits.
- `context.route` only helps ranking (articles related to the page first); `farmId` is ignored in this PR.
- Route review: new route → `routes.snapshot.txt`, allowlist entry with reason (public search mode), permission
  matrix unchanged.

## Model, cost and limits (reusing the existing AI layer)

- Uses the **existing provider seam** (`modules/ai/provider.ts`: `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`), so no new
  secret and the same mock for tests. Model: the configured `AI_MODEL` (today `claude-sonnet-5-5`); no separate
  assistant model (decided). Timeout 20 s, at most 600 output tokens.
- **Usage and cost**: every call is written to the existing `ai_usage_logs` with `feature: 'assistant'` (tokens,
  cost from the existing per-million settings, latency, error code), so the existing admin AI page shows it.
- **Limits** (admin settings): `assistant.enabled` (default **false**), `assistant.dailyLimit` (default 1,000, whole
  platform), `assistant.perUserDaily` (default 20), counted per Thai calendar day. They are separate from the AI
  explanation budget: explanation limits count only explanation rows, and the admin AI page's "used today" against the
  explanation limit does too (its totals and cost include both).
- Rate limit: 60 questions / 15 min per address (`rateLimits.assistant`).
- Rough cost at Sonnet rates ($2 / $10 per million tokens): ~2,500 input + ~300 output tokens per question ≈
  **฿0.3 per answer**; 1,000 questions a day ≈ ฿300/day. The daily limit caps it.

## Safety

- **Personal data redaction before the model**: phone numbers, e-mail addresses, 13-digit ID numbers, bank account
  numbers and LINE ids in the question are replaced (`[เบอร์โทร]`, …) — unit-tested with Thai formats.
- **Prompt injection**: the question and the chunks are passed as data inside clear delimiters; the system prompt says
  they are never instructions; the system prompt is never echoed; output is schema-checked (above) so a manipulated
  answer cannot add links or tours.
- **Scope rules** in the system prompt: only FARM+ usage; no veterinary/legal/financial advice (same disclaimer as the
  AI assessment); say "ไม่ทราบ" instead of guessing; answer in the question's language; short (≤ 6 lines + steps).
- Nothing the person asks is stored: the usage log holds feature, status, tokens, cost, latency and user id only
  (decided: never store question text).

## Web

- A "ถามผู้ช่วย FARM+" panel on `/help`, under the search box (lazy chunk). The header's help button already opens
  `/help`, so the header is unchanged. Shows the answer as plain text (never HTML), the cited articles, page links and
  "start the tips" buttons (only for tours this person can start). Thai and English texts; labelled form, results in
  an `aria-live` region. Not built: a "not helpful" button for answers.
- When `mode: 'search'`, the panel shows the top articles (same look) with a note that answers are switched off.

## Quality check (before switching it on)

- A **golden set of ≥ 30 Thai questions** written the way farmers type ("รหัส sms ไม่มา", "ทำไมสร้างฟาร์มไม่ได้",
  "เพิ่มไก่ยังไง"…) with the expected article. **Target: the right article in the top 3 for ≥ 90%** — this runs in CI
  on the search step alone (no model, no cost).
- The model step is tested with the mock provider (validation, dropped links, redaction, limits, usage log). A small
  manual run against the real model (a few cents) before turning it on in staging — with your go-ahead.

## Contextual tips (PR 5, built)

Fixed server rules decide what is suggested; no model is involved (the brief allowed AI only to reword tips, and that
is not built: the web words every tip from its TH/EN catalog by rule, so nothing is sent to a provider).

- `GET /api/v1/assistant/suggestions?route=&farmId=` (signed in). With `farmId`, farm access is checked first
  (`loadFarmAccess`: a farm the caller cannot see is 404). Returns at most 3 tips, warnings first, then actions, then
  information: `{ key, rule, severity, params, action: { route } | { tourId } }`.
- `PUT /api/v1/me/assistant-tips/:key` `{ action: 'hide' | 'snooze' }`: the caller's own choice, in
  `assistant_tip_states` (unique `userId + key`). Snooze = back on the 7th Thai calendar day after today.

| Rule                                                  | When                                                                                        | Shown to                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------- |
| `create-farm`                                         | no farm, may create one                                                                     | the person                   |
| `owner-request` / `owner-request-pending`             | no farm, may not create one; reason when refused / request under review                     | the person                   |
| `first-animal`                                        | farm has no animals on it                                                                   | members with `animals.write` |
| `weigh-overdue`                                       | animals not weighed in `farms.growthCheckDays` (existing dashboard figure)                  | members with `records.read`  |
| `growth-outside`                                      | latest weight outside the growth criterion (existing figure)                                | members with `records.read`  |
| `withdrawal`                                          | animals on the farm with a health record whose `withdrawalEndsOn` is today or later         | members with `records.read`  |
| `seller-apply` / `seller-rejected` / `seller-pending` | animals marked for sale but no seller access; refused (with reason) / under review          | owner or manager             |
| `offers-waiting`                                      | open offers whose turn is this person's (buyer, or seller side of their farms), not expired | the person                   |
| `listings-in-review`                                  | own listings in `PENDING_REVIEW`                                                            | the person                   |
| `enable-mfa`                                          | has the seller role, two-step sign-in off                                                   | the person                   |

- Not built: "add and verify a second contact channel" — FARM+ has no way to add a phone or e-mail after
  registration, so there is nothing to link to. No rule uses costs, so staff without `expenses.read` lose nothing.
- Web: cards at the top of the assistant panel on `/help` (person tips) and under the farm dashboard's header (person
  and farm tips), each with its action, "เตือนอีกครั้งใน 7 วัน" and "ซ่อน".
- Release: new collection with a unique index → run `pnpm --filter @farmplus/api db indexes --apply --confirm-db
farmplus` for staging (the collection works without it, but the uniqueness is then not enforced).
